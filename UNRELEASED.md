# Unreleased

### Added

- New security checks run on every instruction file each agent loads (`CLAUDE.md`, `AGENTS.md`, rules, skills, agents, commands, hooks, MCP config) and on the files they import with `@path`:
  - `CORE:G:0010` reports invisible Unicode that hides text from a reviewer while the agent still reads it: tag characters, BiDi overrides, zero-width characters and invisible operators. Emoji sequences (skin tones and flags included), joiners inside Arabic-script and Indic words, and a byte-order mark at the start of a file or of an imported file are left alone.
  - `CORE:G:0011` reports a personal home-directory path such as `/home/<name>/`, `/Users/<name>/` or `C:\Users\<name>\`. Windows system profiles such as `Public` and `Default` are left alone. Like `CORE:G:0013`, it checks committed files only, never `.claude/settings.local.json` or your own memory files.
  - `CORE:G:0012` reports a command that downloads code and runs it unseen, such as `curl … | sh`, `bash <(curl …)` or `irm … | iex`.
  - `CORE:G:0013` reports personal data: a US social security number, an international phone number, a MAC address, a public IPv4 address, a personal email address or a crypto wallet address. Version numbers, public DNS resolvers, role addresses such as `security@`, SSH targets and a declared `author` or `contact` email are left alone.
  - `CORE:G:0014` reports text that tells the agent to drop its other instructions or to hide its own actions or instructions from the user.
  - `CORE:G:0015` reports a command that reads a credential store (`~/.ssh/id_*`, `.aws/credentials`, `.netrc`, …) or uploads a local file or the environment to a remote host. Public keys, `authorized_keys` and a token written as an environment reference are left alone.
- New skill checks report a skill that some agents drop or degrade: a name over 64 characters or containing `anthropic` or `claude` (`CORE:S:0059`), a description over 1,024 characters (`CORE:S:0060`), Cursor rule fields `alwaysApply` or `globs` (`CORE:S:0061`), a duplicate frontmatter key (`CORE:S:0062`), tab indentation in the frontmatter (`CORE:S:0063`), and a frontmatter key that YAML reads as a non-string (`CORE:S:0064`).
- `ails xray` reads the agents a Claude Code Workflow run starts, with their loads and hand-backs, and a live page keeps refreshing while a run's agents work.
- `ails xray` folds every segment before the newest compaction into one band showing its loads, its agents and the context size before and after the compaction, so a long session opens at what the agent holds now. The compaction stripe still lists the files that came back and the files that did not. Selecting an agent or a call in an earlier segment opens it.
- `ails xray` draws the instruction files that one hook made Claude Code load, each within 30 seconds of the last, as one card named after that hook, with its file count and size; opening the card lists the loads. A file loaded again and again, each within 30 seconds of the last, is one card that counts the loads (for example ×21). The card stays when the Hooks layer is hidden, and files it loaded again after a compaction, before or after the agent's next reply, count as loaded again on the compaction stripe.
- `ails xray` shows a Workflow run as a node naming the workflow, its phases, status (running, completed, failed or stopped), agent count and tokens, with each of the run's agents under the phase it ran in. Each agent hands back the output the run accepted from it, shown like any other agent's hand-back, and an agent a stopped run left without one reads stopped; a run whose record cannot be read, or is cut off before it is whole JSON, shows as "not readable" while the other runs and the page still load, and the page redraws when a run finishes.
- `ails xray` lists every hook your settings and plugins declare in the Hooks group, not only the ones that fired, and the header reads fired/declared, each hook handler counted once however many tool names it fired under. A hook that fired in an earlier session of the project reads "not this session · last fired <time> (session <id>)" instead of "never fired"; the page says "checking earlier sessions…" until it has read them.
- `ails xray` says why a declared hook cannot fire: its script lost the executable bit ("never fired · not executable"), its folder is gone ("folder missing"), the script is missing ("script missing"), or a settings file sets `disableAllHooks` to true ("all hooks are turned off", with the file named in the fix; managed settings alone turn off the hooks they declare). A hook matcher is read as Claude Code reads it: `Edit, Write` lists two tools and a pattern such as `^Edit$` is a regular expression. The group header adds "N cannot fire", and the hook's details open on a Health section with the fix, such as `chmod +x <path>`. A hook declared under several matchers reads as fired under each one it ran for, and the last-fired time shows in the page's own session clock. A firing marks as fired every declared handler of its event whose matcher selects the tool, a hook output that names no command included, and Stop hooks are read from the session's stop summaries, a Stop hook that blocked counting once. A script path is read after an interpreter's options and their values (`node -r <module> ./run.js`), and `python3 -m <module>` names no script file.

### Changed

- `CORE:G:0002` (No Credentials) also reports a database connection string with an inline password, a JWT, a Google API key, a Stripe live or restricted key, an npm token and a Slack webhook URL.

- Signing in raises the per-check size limit from 2 MB to 5 MB, and the too-large message says so.

- `ails check`, the MCP `validate` tool and the x-ray page parse each rule's checks once, where they parsed them again for every check run: over 20 `validate` calls the rule-file reads drop from 790 to 130. Findings are unchanged.

- `ails xray` shows what the coding agent adds to the context by itself (system prompt, tool definitions, listings, deferred tools, session context, thinking and its other messages) as one collapsed group in each agent's In context list, so Conversation holds only what you and the agent wrote. Opening an item shows only the text its size counts (text another row already counts is left out, including the instruction files loaded from subfolders, hook messages and listings) and, for thinking and tool definitions, how much of it is readable; for the system prompt it also shows its sections with their shares. Each item has one size across the page and says how it was measured: from the recorded request when there is one, labelled as an estimate otherwise (never called the system prompt then). "Open the system prompt it launched with" selects that agent. The Sources panel no longer lists these items.

- `ails xray` opens each agent's In context list on its latest reply, counted from the last compaction, so a long session no longer lists files a compaction dropped, and its total is that reply's measured size; the heading names the reply's time and says when it is the latest. Picking a call shows the list for the reply that made it, counted from the compaction before it, and the call's "Instructions in context" leaves out files that compaction dropped and that did not come back before the call. Each file's time and reason are those of the load since that compaction, a file a compaction restored shows when it came back and says it was kept in the messages the compaction preserved, a row of the list opens the details of that reply and keeps the list (closing them returns to the call's details), and a source's "Why" and a call's "Context then" read as the list does.

- `ails check -f json` and the MCP `validate` response carry a top-level `format_version`, now `1`, which changes when the shape of that output changes. Its `not_evaluated` list can now also hold `{"file", "reason"}` items for a named target that was not checked, beside the existing `{"rule", "file"}` items.

### Fixed

- Antigravity hooks are no longer expected in `~/.gemini/antigravity-cli/settings.json`, which the Antigravity CLI does not load.

- `validate` and `ails check` now give the same answer for every named target. A folder linked from outside the project is checked for the markdown it holds. A word that is both a folder and a capability tells you which meaning was used. A capability the agent lacks is listed as not checked with its name instead of failing the call.
- A folder is only reported as holding no markdown when it holds none.
- A rule that selects files by whether they are committed, gitignored or user-level now finds them; before, such a rule matched no file.
- `ails test` runs a rule's pattern checks only on the files its `match` selects, as `ails check` does, so a rule pack's fixtures test the rule's real scope.
- A Claude Code memory file that keeps its `type` under `metadata:` no longer gets a "missing frontmatter: type" warning.
- The docs now name `AILS_API_KEY` as the environment variable the CLI reads its API key from, and show a CI job that installs the CLI with `npm` and sets it. `REPORAILS_API_KEY` in the GitHub Action examples is only an example secret name; the Action passes its `api-key` input on as `AILS_API_KEY`.
- `ails check prompts/review.md` on a markdown file no agent loads now checks it as a referenced file, with the same findings, the `Referenced` panel and no score, as when a link reaches it. A referenced file no longer gets the `paths:` frontmatter findings meant for `.claude/rules` files. `ails check ./prompts` checks the markdown files under the folder instead of printing "Create a CLAUDE.md"; Claude Code's worktree copies under `.claude/worktrees/` and plan files under `.claude/plans/` are left out of a named folder, as they are of every scan. A folder with no markdown, a folder whose markdown files `exclude_dirs` or `exclude_files` leave out, a file that is not markdown, a capability the agent does not have, or one with no files in the project is reported by name and not checked, in the text output, the JSON `not_evaluated` list, GitHub annotations and the MCP `validate` reply. When nothing is checked, the text output still says "No instruction files found." with the level, and asks to create the agent's instruction file only when the project has none. `ails check /path/to/folder` on a folder outside the one it runs in checks that folder as `ails check` run inside it does: its files, exclusions, agent and config, not every markdown file in it. A folder written inside the project is checked within it, even when it links to a folder outside. A settings file of another project named from outside it is listed as `other_project`, and the text output says to run `ails check` in that project's folder. A named file an `@`-import reaches keeps its importer's class, and with `generic_scanning: true` a named file's `@`-imported files are checked with it. A capability the agent lacks (`ails check @skils`) is listed as not checked and the run exits 2. `validate` with a file `path` and a folder in `targets` checks the folder's markdown as well. When a word names both a capability and a folder, the output says which one it checked.
- A check-level `disabled: true` override in an agent config now drops that check; before, it still ran and reported.
- A settings file without hooks is no longer reported by a rule that another rule supersedes.
- The x-ray compaction stripe's one-line text stays inside the stripe at 1280 and 1920 px instead of running past it.
- The hidden-character check no longer times out on large files, so it is no longer reported as not evaluated.
- The secret-file and piped-remote-code checks no longer report a settings file's deny list.

- `ails xray`: a row whose details are open keeps its place and layout, with no gap above it, its text left-aligned and its status dot kept.

### Removed

### Internal

- Tests: the hook cannot-fire tests carry their subsystem marker.
- The x-ray graph records are split into two modules and smaller functions; no change in what the page shows.
- Two oversized modules are split, with no change in behaviour.
- The pattern checks scan exactly the files the run checks, so the folders and files `exclude_dirs`, `exclude_files` and `--exclude-dirs` leave out stay out of them; checking one file applies its project's `.ails/config.yml` to the files that file's links reach.
- Tests: the loader refusals for an empty or uncompilable `pattern-either` and a check without an id are covered against the real loader.
- The superseded-check scenario passes without the bundled model.
