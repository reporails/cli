# Unreleased

### Added

- With the reporails plugin installed, a Claude Code session's start and end, prompts, file reads and edits, stops and compactions are recorded locally as event records (which file, which tool, when; never prompt or file text) in a private per-session file under `~/.reporails/xray/`, pruned by age and size. `ails events --session <id> -f json` prints a session's records in the order they were recorded, and `--after <next>` continues from the `next` offset the previous call printed, reading only what was recorded since. Recording never prints into or blocks the session, and nothing is sent anywhere.
- `ails xray` opens a local page that shows a Claude Code session as its agents: the main agent and every subagent, nested ones included, each on its own timeline. Opening a subagent shows the same view of its own work, with the path back up and its parent's other subagents above it. Files show relative to the project, or under `~/`. The page is served on 127.0.0.1 only and reads the session from local files; only the check and fix buttons reach the reporails server, as `ails check` does.
- Each agent's timeline shows the instruction files, rules, skills, memory, MCP servers and hook notes it loaded at the moment they entered its context, its file reads, edits and shell commands beside it, a shell command that failed the same way three times or more as one bracket, and its compactions and long idle stretches. Each subagent shows what it was handed (its task, what it started with, and what its parent held that it did not get), how much work it did, and what it handed back, or that it was stopped, failed, is still running or never handed anything back.
- The Sources panel lists what a session in the folder can load: instruction, rule and memory files, skills and commands, MCP servers and hook notes, from the project, your user folder, the skills synced from your claude.ai account (`anthropic-skills:<name>`, the signed-in account only) and every installed, enabled plugin (`<plugin>:<name>`), each with its size, whether it loaded, was only listed or never loaded, and which agents had it. Each kind is a group that opens on click (the first kind starts open, "Expand all" and "Collapse all" switch every group, and a long group shows four sources with "Show more"). Focusing a source opens its group and lights the agents that had it; a memory file that `MEMORY.md` does not link is marked, and each source shows its estimated cost across the session.
- Each agent shows its context at every reply: the total exactly as the API reported it (fresh input, cache writes, cache reads), split into instruction files, rules and loaded skills, the skills listing, memory, hook notes, conversation and tool results as `~` estimates, with what the estimates leave counted as the system prompt and tools; a compaction clears the conversation, tool results and hook notes before it, and a hook note that arrives after it counts from then on. The agent's spine is as wide as its exact context, with the estimated split drawn as bands inside it; loads that land close together merge into one "3 loads" mark, and the passed-down and came-back sizes show for the selected agent. Each agent shows what its replies cost at Claude API list prices (named and dated on the page; on a subscription you do not pay per token) and how much of its context came from the cache.
- Subagents launched within moments of each other are grouped as one fan-out card that expands on click (and opens by itself when it holds the selected agent, so going back up from a subagent shows it selected in its group); every card sits at its launch time, the time scale stretches where agents fan out and marks where it did, a hook that fires again and again shows as one stretch, and user-defined agents (`.claude/agents/`, `~/.claude/agents/`) and the built-in agent types are sources of their own, each with how many subagents were launched from it.
- Prompts, subagent tasks, failing commands and file text are read on request and never stored, and names and text always show as plain text. The page names the model and its context window, checks the project's files once when it opens so each file's findings show without a click, and opens a file's findings, each with its severity, rule title, category and docs link, and the command that fixes the file.
- The x-ray page has a session switcher in its header: the button shows the open session's start time, length and subagent count, and the list shows every session of the project the same way, with a "first prompt" toggle per session that reads the prompt only when clicked. Picking a session opens it. When the agent did not say which session it is, the page shows the folder's newest session and says so.
- A coding agent can open the x-ray page itself: the reporails MCP server has an `xray` tool, the reporails plugin has `/reporails:ails xray`, and `ails xray --background` starts the page detached, prints its address and returns, so the agent's call does not wait. A page already running for the project is reused, and `ails xray` in a terminal registers its page for the same reuse.
- `ails xray --current` opens the session of the agent that runs it, even when a newer session of the folder exists, and the newest session when the agent does not say which session it is. `--session` with `--current` is refused, and `--session` with an id that is not a session of the folder is refused with the folder named.
- The x-ray page lists every tool call of every agent with its tool, MCP server, how long it took and the estimated size of its result, counts each agent's calls per tool, and opens any call's input and an excerpt of its result on request (read from the session transcript, never stored).
- The x-ray view lists the coding agent's own context (system prompt, tool definitions, agent and skills listings, session context) with their estimated sizes, lists built-in agent types beside your agent definitions with how many subagents each launched, names each source by its kind (a rule's file name and path patterns, a memory note without its type prefix, an MCP server with each tool's call count), and lists for every agent what was in its context at its peak, adding up to the exact total. The view also carries the session's total estimated cost, never takes a background launch's acknowledgement for what a subagent handed back, words counts of one in the singular, and says when the transcript recorded no instruction-file loads instead of showing them as not loaded.
- The x-ray page has Graph, Tool calls and Sources tabs, each with its count; a session without subagents opens on Tool calls. Hovering or focusing highlights without moving anything, clicking an agent inspects it, clicking a source opens its details over the graph, and Esc closes the details, then clears the selection. Each Sources group has an eye button that shows or hides that kind on the graph, the page fits a 1280 px screen without scrolling sideways, and every text meets 4.5:1 contrast at 10.5 px or larger, also when the graph is scaled down or an item is dimmed. Keyboard focus stays where it was when the page redraws and returns to the control that opened the details, the tables are grids that arrow keys move through, small controls have 24 px targets, and below 760 px the page is one column.
- The x-ray page's Tool calls tab lists every call of the session with its time, agent, tool, result size, duration and status, filters it to one agent, one agent and its subagents, one tool or the failed calls, draws the filtered calls on a timeline, and shows a shell call's command, and opens a call's input, result, context at that turn and the instruction files in context; the Sources tab lists every source and built-in item with the agents that had it, its size and its findings. Both tables stay fast with thousands of rows, and with no details open the side panel shows the agent's own summary, so a session without subagents still opens on its cost, peak context and what was in it.
- The x-ray graph puts what entered an agent's context on the left of its spine (one node per source at its first load, one per MCP server with a round trip to each burst of its calls) and its subagents on the right, keeps only hooks on the spine, shows the selected agent on its collapsed fan-out group, and adds a jump rail beside the graph with the calls' density and markers for repeated failures, fan-outs, the selection and the end. Hiding agents removes every subagent from the graph.
- The x-ray Sources panel is an inventory of everything a session could load, built-in context first: each group shows how many of its items were used and its findings, each item its size, estimated cost and findings, and an eye button shows or hides a kind on the graph without changing the list. The right column always shows one agent: its peak context and estimated cost (each opening a breakdown), everything that was in its context at its peak, its tool calls per tool (each opening the Tool calls tab), its subagents and, for a subagent, what it returned. A source's details show its findings, configuration, path patterns or MCP tools, its full text, which agents loaded it and how its cost is estimated.
- The x-ray view says how its session was chosen (named, the calling agent's own, or the newest), and `python -m reporails_cli` runs the same command as `ails`.
- On Claude Code 2.1.309 or later, an agent type's details in the x-ray page (a built-in type such as `general-purpose` or `Explore`, or one of your agent definitions) show the system prompt its subagents were launched with (its size, and its text read from the session file when the details open, never stored) and each tool they were sent with, counted by the launches that had it, instead of saying the text comes from the coding agent. A type none of whose launches recorded a request keeps today's details.

### Changed

- On Claude Code 2.1.309 or later, each agent's context in the x-ray view is split from the request Claude Code recorded: the In context list shows the system prompt, the tool definitions, the tool calls and results and the conversation as measured shares of the exact total, with no remainder row, and the coding agent's own context lists the tool definitions sent with every request beside the deferred tools. The skills listing keeps its own estimated row beside the conversation. A reply keeps the estimated split, labelled "Estimated: no complete recorded request for this reply.", when its request was not recorded (an older Claude Code), names a message the session file does not hold, or has a request row the view cannot read; that row is listed with its file and field, and a message with a lone surrogate no longer stops the read.
- The folder you run `ails check` in is the project root. A file or folder inside it is checked within that project, an agent folder such as `.claude/rules` included; a folder outside it is checked at itself, a file outside it at its own folder, and a file under `~/.claude` at `~/.claude`. Nothing walks up from the target looking for `.git`, `.ails/backbone.yml`, editor folders or agent folders.
- `ails check <file>` says so when the file is not an instruction file of its project (`<file> is not an instruction file in the project at <root>; run ails check in that project's folder.`); the exit code is unchanged.
- The reporails MCP tools (`validate`, `prepare`, `remedy_brief`, `heal_apply`, `xray`) never use the folder the server was started in. They use the `path` the agent passes, else the agent's project folder that holds that `path`, else an absolute `AILS_PROJECT_DIR`; with none of these a tool answers `no_project` and asks for the project folder as `path`, and a bare file `path` with no agent folder is refused too. An agent that never answers the folder request no longer stalls a tool (it waits 2 s), `file://` folders from Windows and network shares are read correctly, and one path under two project folders keeps its own repeat-call counters. Claude Code and VS Code tell the tools which folder the project is; in Cursor, Codex and Antigravity the agent passes it as `path` when a tool asks.
- `ails check` on a folder inside `~/.claude` (for example `~/.claude/skills`) checks and heals only that folder, not the rest of `~/.claude`. The MCP tools checking a folder keep its symlinked instruction files, as `ails check` does.
- `ails install --project` installs for the folder you run it in, and refuses to run in your home folder.
- `ails xray --current` and the agent's `xray` tool find the agent's own session by its id in any project and open it on the folder that session ran in, so they work from a subfolder of the folder Claude Code was started in. Plain `ails xray` reads only the sessions of the folder it runs in; with none it exits 2 naming that folder.
- `ails expected-loads` also lists the skills, agents, commands and hook configs a session in the folder can invoke, from the project, your user folder, the skills synced from your claude.ai account and every installed, enabled plugin, and says for each memory file whether `MEMORY.md` links it within the part Claude Code loads. A malformed `installed_plugins.json` ends the command with the error and exit 2.
- Antigravity rules are now also found in `.agent/rules/`, `~/.gemini/antigravity-cli/rules/` and plugin `rules/` folders, and plugin `mcp_config.json` files are checked as MCP config.
- The Codex, Copilot, Cursor and Antigravity agent pages now state what each agent's docs say: Codex custom agents cannot override sandbox, approval, provider or MCP settings, Copilot's `excludeAgent` takes `cloud-agent`, Cursor ignores a plain `.md` in `.cursor/rules`, and Antigravity keeps hooks in `hooks.json`, not `settings.json`.

### Fixed

- On the x-ray page, an instruction or memory file the session loaded shows its text, as the kind it is, even when the project's config leaves its folder out of the checks (it had read "not a file this page lists"), with no check or fix offered for it; and when the page takes a new view of a growing session, a panel whose content did not change is left as it is and an open file text no longer flashes "Loading…", so the page no longer flickers.
- An x-ray page stops by itself after 30 minutes with no request (`AILS_XRAY_IDLE_S` seconds; `0` never stops), so a page an agent started in the background no longer runs until it is killed by hand. A page left open in a browser tab stays up.
- `ails xray` opens its page even when `~/.reporails` cannot be written (the page is then not reused by a later call), and the agent's `xray` tool answers `page_not_started` naming the folder instead of failing.
- A `heal_exclude` entry that is a bare file name now matches only at the project root, as documented, and the findings listed as `excluded` name the files they sit in.
- The hook event-type check for Antigravity, Codex and Copilot now accepts each agent's current hook events — Antigravity's `SessionStart` and Codex's `PreModelRequest` / `PostModelRequest` among them — instead of reporting them as unrecognized.
- An `@import` that resolves outside the current project is left as a literal reference instead of pulling that file's content into the check.
- `--heal` on a single file no longer writes through a symlink whose real path points outside the project.
- Files from your home folder and from installed plugins are found by walking only below their own folder, skipping `node_modules` and the other left-out folders, and a plugin folder with `[` or `*` in its path is read as written.
- A stored API key is sent only to the default server or a local (loopback) address, never to any other `AILS_SERVER_URL` the cli is pointed at.

### Removed

### Internal


- The `ails xray` page bundles the Inter and JetBrains Mono fonts (SIL Open Font License), so it loads no web fonts.
- Release and CI builds install from the lock file with a fixed `uv` version, a fixed `hatchling` version and commit-pinned GitHub actions.
- Tests: a property suite runs the real `ails` and the MCP server over a fixture set in text, JSON, `github` and MCP, and checks on every run that a disabled rule appears in no output, the total equals m_probe + client + server, every format carries one finding set, and the exit code matches the findings; the mutation probe accepts an upper-tier killing command.
- Tests: the unit tests for the per-source finding counts are removed; the total-equals-sum property covers them.
- CI runs the behavioral scenarios on every pull request, not only in the release gate.
- Tests: a skipped api-backed scenario leaves no temp directory behind, and the mutation probe's `--timeout` applies to a pytest target too.
- Internal restructuring of the package boundaries: every data record lives in one layer; command output is unchanged.
- `AILS_STAGE_TIMING=1` also prints the time of heal and of each MCP tool call.
- The torch import blocker is removed; nothing the cli installs imports torch.
- Tests: architecture checks guard the package boundaries, replacing two narrower checks they cover, and `poe hexagon` renders the package dependency view.
- Tests: `poe test_behave` runs the behavioral scenarios in parallel processes that share one headless browser each, waits on page state instead of fixed pauses, and holds the performance power profile while it runs where `powerprofilesctl` offers one (`BEHAVE_POWER=keep` skips that); two scenarios check that each agent's context adds up to its exact total from the recorded request, and that an older session is labelled as an estimate.
- Checking or fixing one file runs through one shared path for every interface; MCP replies are unchanged, and an architecture check stops one interface importing another; a test shows the page's fix button writing every fix and putting back a file that departs.
- On the x-ray page, images in a session no longer push up the measured system prompt, tool definition and tool call shares: each image is counted at its own token cost (from its size, at the rate of the model that received it) in the row that holds it, a request holding an image or document the page cannot price keeps the estimated split, and the rows still add up to the exact total.
- On the x-ray page, a measured row of a subagent (system prompt, tool definitions, tool calls and results) opens that subagent's own figure instead of the main agent's, and shows how it was measured: the request, its characters, tokens per character, image tokens and what is already listed above.
